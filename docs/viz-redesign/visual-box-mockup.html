P0

Fix header, separators & sectioning first

Sticky panel header with a p-menu overflow (Reset / Advanced JSON); convert the 67 config-sections to p-accordion panels, only Data + primary options open by default. Pure presentation over the existing DOM — lowest risk, directly answers "below standard."

P0

Data / Format tabs + carry re-query flag

Two p-tabs, Data first; fold the field tree in beside the role slots. Change the emit to configChanged.emit({ config, requiresRequery }) so format-only edits skip the server round-trip and just re-run chart.setOption().

P0

Bound fields become clickable pills

Wrap each bound column in an app-chip that opens a p-popover: column ▸ aggregate ▸ (percentile / date-trunc) ▸ alias ▸ remove. Shows SUM(Revenue) inline — the single biggest discoverability win.

Chart card & ECharts theme

echart-visual · configurable-card-chart

The chart renders, but the card frame and default ECharts look are generic. The highest-leverage single fix is a registered DBExec ECharts theme so every chart inherits the palette, type scale, gridlines & tooltip in one place.

Fix: one kebab for actions, a registered DBExec ECharts theme (brand palette, tabular-nums, faint grid, styled tooltip), consistent body padding, and framed empty / error / loading states.

P0

Register a DBExec ECharts theme

One echarts.registerTheme('dbexec', …) so palette, axis, gridline, tooltip & type scale are consistent across all 24 types — instead of per-chart option tweaks. Highest leverage in the whole chrome track.

P0

Collapse the header icon-soup into a kebab

Move export / duplicate / refresh into a single p-menu kebab; keep only the title, subtitle (context: period, unit) and the menu on the header row.

P0

State components inside the card frame

Error, no-data and loading render inside the card (icon + message + retry), not as a blank canvas or a global spinner.

Interaction model

cross-filter · drill · tooltip

Cross-filter exists but is fragmented across modes; the active-state surface (what's filtering what) is what reads as unfinished. The fix is one source→target action primitive and a clear active-filter chrome.

P0

Unify on one source→target action model

Collapse the 3 cross-filter target modes into a single action: a chart click emits {source, field, value}; targets subscribe. One code path for same-tab, dashboard & explicit-visual scopes.

P0

Show the active filter state

A dismissible active-filter bar / chip on filtered charts ("Filtered by Region = EU ✕") — the missing visual that makes cross-filter feel finished.

One-line takeaway: keep the 24 chart types; spend the effort on the config-panel UX, a shared ECharts theme, and a unified interaction model. Wave 1 alone closes most of the "looks below standard" perception at almost no risk.
