## 1. Context
- Responsibility: The semantic layer. A dataset = a saved SQL query against a datasource + typed field metadata + calculated fields + `{{name}}` query params. It's the source for analyses/dashboards/RLS/alerts.
- Key files:
  - `components/add-dataset` + `edit-dataset` — the editor: **Monaco** SQL editor (`MonacoLoaderService` + `MonacoIntelliSenseService`, lazy schema tree pre-warm), result grid (p-table, not AG Grid), diff-before-save (`preview-columns`), save-and-run, column profiling + CSV/JSON export.
  - `components/calculated-fields-dialog` — **Engine 1** UI (SQL `[bracket]` compiler; no function palette; entity `CalculatedField`).
  - `components/add-custom-field-dialog` — **Engine 2** UI (JS `{brace}` FormulaCompiler; Monaco `formulaLang`; `constants/functions-reference.ts` = ~137-function QuickSight-style palette; writes `DatasetField.customLogic`).
  - `components/dataset-params-panel` + `helpers/param-tokens.helper.ts` — `{{name}}` param tokenizer (ignores string-literals/comments; mirrored BE `datasetParams.ts`), static + query-based dropdown options.
  - `components/edit-dataset-fields-dialog` — rich column metadata editor (description/role/defaultAggregation/formatHint/isVisible/typeOverride).
  - `services/dataset.service.ts` (HTTP+signals), `calculated-fields.service.ts`, plus SQL helper services (formatter/linter/validator/scope-tracker) and `config/sql-dialects/` (postgres/mysql/mariadb/mssql/oracle/snowflake).
- Depends on: **datasource** (schema introspection + runQuery). `DATASET` api/routes constants. Mirrored Zod `validators/datasets.ts` + `calculatedFields.ts` (byte-identical FE↔BE).
- Depended on by: **analyses** (dataset picker + fields), **dashboard**, **rls-rules** (rules bind to a dataset), **alerts**, **migration** (export/import + dependency inclusion).
- How it works: List (`app-custom-table`, Datasource column + optional filter). Add/Edit: pick datasource → write SQL (params tokenized) → run preview → map/type fields → add calc fields (either engine) → Save (versioned on BE). View: freshness, field metadata, delete-dependency guard via lineage.
- Decisions: **TWO calc-field engines, do not confuse them** (see [calc-field-engines memory]): Engine 1 = SQL `[bracket]`, pushed DOWN to warehouse as SQL, AST-compiled + whitelisted. Engine 2 = JS `{brace}`, runs per-row in Node AFTER the query (enrichment). `concat({a},{b})` uses Engine 2. Result section deliberately uses p-table (us-data-grid reverted). See [ARCHITECTURE.md](../ARCHITECTURE.md).
- Gotchas / constraints:
  - **Save is VERSIONED** — each save clones into a new-version row (new id, same `lineageId`) and returns the new id; the analysis-save-persistence "bug" was a stale-id test artifact, not data loss.
  - **Field metadata is mostly DEAD/UI-only** (aggregation-field-audit): `role`/`defaultAggregation`/`formatHint`/`isVisible`/`typeOverride` are stored+returned but the BE has ~zero consumers — the editor writes columns the backend never reads. Don't assume `isVisible` hides columns or `defaultAggregation` auto-picks.
  - Engine 2 `add-custom-field-dialog` naming is confusing: formula stored in `customField.columnToUse`, display name in `columnToView`.
  - Save `/datasets/:id/fields` needs `datasetId` in the BODY too (not just URL) or 400.
  - Engine 2 enrichment re-parses the formula per-row (O(rows × parse)); length cap 4000 + max-paren-depth 32 bound the worst case (DoS fix).

## 3. Progress (newest first)
### 2026-07-28 — Editor unification: one Monaco editor, theme, options and service
- **CodeMirror is gone.** The Query Executor was the last editor not on Monaco, which is what kept the three modules from ever looking alike. Nine packages removed (`@codemirror/{view,state,commands,autocomplete,search,lint,language,theme-one-dark}`, `codemirror`, `@replit/codemirror-minimap`), plus `completion.ts`, `search-panel.ts`, `_codemirror-theme.scss` (296 lines) and ~90 lines of panel SCSS. `@codemirror/lang-sql` stays — see the note in `sql-dialects/index.ts`: it supplies keyword word lists AND a Lezer parser used only by the currently-disabled dialect lint.
- **New `src/app/shared/editor/`** — `CodeEditorService` is now the ONLY place `monaco.editor.create` is called. It owns load → register language → define theme → create → re-assert the global theme → focus → dispose. Five hand-rolled copies of that sequence had already diverged. It also closes two traps for every caller: Monaco fires outside Angular's zone (an OnPush component never re-rendered — a Run button stayed grey while typing), and partial disposal leaked completion providers. Plus `monaco-theme.ts`, `monaco-options.ts`, `formula-language.ts`, `editor-doc.ts`, `editor-placeholder.ts`, `run-flash.ts`, `schema-bridge.ts`.
- **IntelliSense upgraded, not ported.** The executor's own 237-line completion source was replaced by the dataset module's 2,272-line `MonacoIntelliSenseService`, adding CTE scope tracking, alias generation, INSERT/UP2026-07-28 column lists and six dialects. Its lazy column loading was preserved by two additions: `schema-bridge.ts` projects the lazy `SchemaCatalog` into the tree the service reads, and `setColumnRequestHandler` lets the service ask the consumer to fetch a table's columns — hooked at `resolveScopeRefs`, the single choke point where a SQL reference becomes a table schema, so dot completion, clause-scoped columns and alias resolution are covered by one call.
- **Corrections to earlier assumptions:** (1) there is **no dark mode** — four components branched on a `dark-theme` body class nothing ever adds, so Monaco always rendered light and three copies were identical dead code; (2) the theme must be built at **runtime from computed tokens**, because `ThemeService` rewrites `--primary-color` per organisation, so hard-coded hex gave a branded org a stock-blue editor.
- **Six real bugs found by the new suites**, each of which had passed a weaker assertion first: the bridge enumerated only table *listings* and hid lazily-fetched columns; it emitted `dataType` where the service reads `type` (every column read "undefined"); `triggerSuggest` could not refresh an already-open widget (exactly the lazy case); Monaco's `addCommand` **and** `addAction` never bind here, so shortcuts use `onKeyDown` with explicit matching; and the parity spec's own auth helper silently returned an empty token.
- **Chrome converged** onto shared mixins: panel headers, dense tree rows, buttons. One deliberate non-convergence, recorded in the mixin — the object browser's rows are not turned into bordered cards, because a schema tree of hundreds of nodes becomes far taller and loses the nesting that makes a tree legible.
- Verified: `tsc` + `ngc` + production build clean. **16/16** formula, **37/37** formula screenshots, **7/7** executor, **1/1** parity (four components report identical `fontFamily`, `fontSize` 14px, `lineHeight` 22px, background and gutter), **3/3** showcase. Screenshots in `screenshots/` with a README.
- Known / next: `docs/superpowers/plans/2026-07-28-dataset-component-decomposition.md` maps the file-size work. 84 of 96 methods are shared between add- and edit-dataset — 35 byte-identical, **49 drifted** (the same feature behaving differently when creating vs editing). Blocked on functional e2e for dataset create/edit, which does not exist yet.

### 2026-07-27 — Pushdown removed: everything computes on the API
- Done: the tier badge is gone. Derived fields are no longer described as "computed at source" vs "computed after query" — **every formula is computed on the API server**, so the badge now reports the CALCULATION KIND instead: Row / Aggregate / Window (`DATASET.STAGE_ROW|STAGE_AGGREGATE|STAGE_WINDOW`), with a standing note under it: "Computed on the server after the query. To filter or aggregate on a computed value at the database, put the expression in your dataset SQL." `pushdownable` dropped from `FormulaFunction`, `DatasetFieldVm` and the sidebar; `tierKey`/`tierBadgeKey` renamed to `stageKey`/`stageBadgeKey`. Retired i18n keys `FORMULA_AT_SOURCE`/`FORMULA_AFTER_QUERY`; added 4 new keys across all 10 locales.
- Why: the SQL tier was ~50 functions × 6 dialects of hand-written fragments that could not be executed in a unit test, and it produced real divergence — division by zero RAISING in Postgres where the interpreter returns null, and a MySQL date-truncation template that silently returned the wrong period while all 264 harness checks passed. One implementation cannot disagree with itself. The escape hatch is better here than in Looker or Tableau because the author writes the dataset SELECT: putting the expression there makes it an ordinary column that the filter and aggregation wraps use directly.
